## システム構成

- ブラウザ上のReactアプリ。サーバー、利用者アカウント、外部APIは使わない。
- 地図は10章・10目的地の案。教材順の一本道と6つの景観地域を持つ。
- 教材画面と修了証は現行のURL遷移の枠組みを維持し、地図画面へ戻ると次の章を現在地として表示する。
- 学習進捗・獲得品・装備選択は端末内localStorageに保存する。

## 進捗とデータ

### 新しい保存領域（案）

`mind-seeker-progress-v2` を新スキーマの保存キーとする。現行キーは `mind-seeker-learning-progress-v1`。旧キーと値は読み取り専用で残し、書き換え・削除しない。新形式の保存に失敗した場合、旧データを保持し、移行完了と扱わない。

- `schemaVersion`: 数値。移行済み形式を判定。
- `chapters`: 章IDごとに `completedUnitIds` と `lastUnitId` を保持。
- `ownedItemIds`: 獲得装備の集合。
- `equippedBySlot`: 装備スロットごとの装備ID。
- `migration`: 移行元スキーマ、実施日時、案内済みフラグ。
- `reflection`: 初期仕様では保存しない。

完了状態と成長段階は章進捗から導出し、別の真偽値を重複保存しない。獲得装備は章修了処理を同じ章IDに対し一度だけ適用し、再閲覧で二重付与しない。

### 状態遷移

1. 新規利用者: Chapter 01 が `current`、他は `locked`。
2. 教材途中: 完了単位を保存し、`lastUnitId` から再開。
3. 必須教材完了: 章を `completed` にし、修了証と報酬を一度だけ付与。次章を `current` にする。
4. 章再閲覧: 完了状態は維持。再完了処理で報酬を再付与しない。
5. 全章完了: すべての章を再閲覧可能。最終まとめと全装備を確認できる。
6. 旧データ移行: v1保存を読む専用ブートストラップを現行Rootの正規化・v1保存より先に実行する。旧ステージIDを章順の移行コホートへ対応させ、条件を満たす最長の連続章だけを完了扱いにする。教材IDが再配置されるため未完了章は章頭から開始する。旧キーは保持し、新形式を一度だけ作成する。v2保存の成功後に新UIを開始し、v1保存effectは除去または隔離する。

### 教材完了

- 必須教材単位は章の進行順に提示する。選択練習は回答後に理由・影響を解説し、正解を選ぶまで進めない形にはしない。
- 「現実で試す行動」と「振り返り」は任意。初期リリースでは文章をサーバー保存せず、自由記述欄も設けない。
- 章を完了する条件は必須教材単位を最後まで表示・回答したこと。現実での実践実績は問わない。

## 目的地・進捗UI

- 町名は使わず、地図には章番号と短い章タイトルを表示する。
- 修了済み: 通常の建物・広場に修了印を付ける。選択して教材を見返せる。
- 現在: 明るい輪郭と「次へ」などの文字ラベルで示す。点滅に依存しない。
- 未解放: 景観としての建物と道は見せ、鍵と低い明度で状態を表す。フォーカス可能な案内ボタンとして操作できるが、教材パネルは開かず、未解放理由をその地点の案内として表示する。読み上げ名にも未解放状態と理由を含める。
- 目的地の操作領域は建物全体を覆うボタンにし、キーボードフォーカス、Enter/Space、読み上げ用状態説明を用意する。
- 目的地ボタンの操作可能領域は各画面サイズで最低44×44 CSS pxを確保する。地図SVGの縮小倍率に依存させず、CSSピクセル基準のHTML/SVG overlayで確保する。建物と章ラベルは同じ目的地ボタンに含める。
- 章タイトルは全10地点で常時表示する。縮小時に重なりそうな場合はラベル位置をずらし、操作可能な現在地を強調する。状態は読み上げラベルにも反映する。
- 選択パネルは選択地点を隠しにくい側に配置し、閉じるボタンとEscapeキーを備える。

## マップ表示・操作

- 6地域は草原→森→山岳→荒野→雪原→水辺。10地点配置例は地域ごと2・2・2・1・1・2。本道は3段S字で下段4・中段3・上段3。
- 地形・建物はアイソメトリック風。町は約6種の建築シルエットを素材差で展開する。塔・橋・遺跡は進捗を持たない景観物。
- PC: 初期表示で全体を把握。拡大時のドラッグ／トラックパッドパンを地図境界でクランプし、背景色は地図端の地形色に合わせる。現在地へ戻る操作を置く。
- スマートフォン縦: マップを画面幅に合わせ、必要な高さはページ内スクロールで見る。横方向のパンは原則させない。
- スマートフォン横: 可能な範囲で全体表示。狭い場合はタッチパン可能とし境界をクランプする。
- 章完了で次章が解放されたら、演出後に次章詳細を開く。ユーザーが別の画面操作をした場合は、勝手に現在地へ戻す追従を続けない。
- 画面向き変更とウィンドウリサイズで地図内位置を再計算する。

## キャラクター成長と装備

- キャラクターはステータスパネルにのみ置く。初期姿は「質素な旅装の旅人」とし、困窮やホームレス状態を笑いの対象にする演出はしない。
- 基礎姿は初期＋2章ごとの成長で計6段階を案とする。どの章数でも外見の変化が見えるよう、各章の修了報酬アイテムを別に付与する。
- 章の修了証に1アイテムを結びつける。アイテムは装備スロットを持ち、獲得時に空きスロットへ自動装備。スロットが埋まっている場合は所持品に加え、ユーザーが装備画面で選ぶまで現在装備を変えない。
- 所持品・装備変更は端末内保存。全章をやり直しても報酬を重複付与しない。
- アニメーションは短いフェード／スケール程度。動きを減らす設定では静止表現にする。

## 章構成案と旧ステージ対応

次の対応表は教材テーマ再編のたたき台であり、素材参照先であって進捗移行用の所属ではない。実装開始条件として、別の確定データ表に `chapterOrder`、各章の `legacyStageIds`、`requiredUnitIds` を明示する。移行用IDは章順のコホートに一度だけ割り当て、36 IDの重複・欠落がないこと、章完了が最長の連続完了プレフィックスになることを確認する。新規・横断教材は旧完了を付与しない。2026-09-27の実装指示により以下の10章テーマを採用する。

| 章案 | 学習テーマ案 | 主な素材（移行所属ではない） |
|---:|---|---|
| 1 | 主体的に選ぶ | stage-01〜04 |
| 2 | 目的を定める | stage-05〜07 |
| 3 | 優先順位を決める | stage-08〜10 |
| 4 | 互いに納得できる案を探す | stage-11〜12、25、28 |
| 5 | まず理解してから伝える | stage-13〜16 |
| 6 | 違いを活かして協力する | stage-17〜20、29〜32 |
| 7 | 自分を整え続ける | stage-21〜24、26〜27 |
| 8 | 自分の習慣を組み合わせる | stage-33〜34 |
| 9 | 人との課題に活かす | stage-35＋既存対話・合意・協働事例 |
| 10 | 振り返り、次の行動を決める | stage-36＋全体統合 |

章ごとに4〜6教材単位を目安とし、教材本文の棚卸しで決定する。上表のステージ範囲は連続範囲を示す案で、章4・6・7・9などの横断再編は明示ID一覧にする。文章の転載や機械的な連結はしない。

### 旧進捗の移行コホート案（テーマ素材表とは独立）

旧進捗だけを順序どおりに移すため、旧36ステージを次の10個の連続コホートへ機械的に分ける。これは教材テーマの所属や新教材内容を意味しない。完了済み旧ステージ数に応じ、条件を満たす最長の連続コホートだけを新章修了として引き継ぐ。コホート内の全旧ステージ完了をその章の条件とし、後続コホートだけ完了していても飛び越して移行しない。

| 新章順 | 移行対象の旧ステージID |
|---:|---|
| 1 | stage-01〜04 |
| 2 | stage-05〜08 |
| 3 | stage-09〜12 |
| 4 | stage-13〜16 |
| 5 | stage-17〜20 |
| 6 | stage-21〜24 |
| 7 | stage-25〜27 |
| 8 | stage-28〜30 |
| 9 | stage-31〜33 |
| 10 | stage-34〜36 |

各 `stageId` はこの表に一度だけ現れる。新規作成または複数ステージを横断して作る教材単位は旧進捗を付与しない。新教材の `requiredUnitIds` は教材棚卸し工程で別表として確定する。

## 主要処理フロー

### 章を修了する

1. 必須教材の最終単位を完了する。
2. 章進捗を保存し、章IDが未完了なら修了済みにする。
3. 対応する修了証・装備報酬を付与し、空きスロットがあれば装備する。
4. 成長段階を完了章数から導出する。
5. 次章を解放し、修了証画面で報酬・次の目的地を示す。
6. 地図に戻った時点で次章を現在地として表示する。

### 旧進捗を移行する

1. 新形式が存在する場合は移行済みとして扱い、二重移行しない。
2. 現行Rootの正規化やv1保存effectより前に、移行専用処理が `mind-seeker-learning-progress-v1` を読み、JSONと配列要素の型を検証する。
3. 章順の移行コホートごとに完了条件を評価し、条件を満たす最長の連続章プレフィックスだけをv2へ移す。後続条件を満たしても先行章が未完了なら移さない。
4. 新形式を保存する。成功前に新UIを開始しない。失敗時は旧記録を維持してエラー案内を出す。
5. v2保存成功後に旧v1保存effectを除去または隔離し、以後v1へ書き戻さない。
6. 旧途中教材は旧JSON内に残るが、旧教材の再読・再開画面は提供しない。新章は章頭から開始する旨を一度案内する。

## セキュリティ・プライバシー

外部送信はしない。学習進捗と装備は利用中のブラウザ端末内に保存し、別端末へ自動同期しない。自由記述は初期仕様に含めない。利用者がブラウザ保存領域を消去した場合の復元はできないため、必要ならアプリ内で説明する。

## 配布・開発フェーズ

- 現行の静的サイト配布経路を維持する。公開前にローカルビルドと各画面サイズで検証する。
- 実装は地図アセット試作、地図・カメラ、章進捗と移行、キャラクター・報酬、統合確認の順に分ける。
- ブラウザテストランナーは未導入。プロジェクト宣言に従い自動テスト工程はスキップし、build/lintとブラウザ実測で代替する。

## 仕様書で新たに決めたこと（提案値）

1. 章数・町数を10、教材は1章4〜6単位、修了を章単位とする。
2. キャラクター基礎姿は6段階、章修了報酬を各1個とする。
3. 旧進捗は削除せず、旧ステージ対応表で完全な章だけを移行する。
4. 振り返りの自由記述は初期版に含めず、外部共有しない。
5. PCは全体表示から開始し、拡大時のみ境界内パン。縦スマホは縦スクロール。
6. 新章への旧進捗移行は、現行ローダーが有効と認識する連続完了ステージを根拠にする。途中教材の元データは旧キーに保持するが、新章内の再開位置には引き継がない。

## 実装しないこと

- マップ上の歩行キャラクター、町名決定、分岐ルート、オンライン保存、同期、自由記述のクラウド送信、実生活の行動完了を条件とする章ロック。

## 提案値つき未決事項

- 代表タイル試作でのセル寸法、画風、画像形式、総容量、初回ロード時間。提案: 128×64論理セルを起点に測定し、細部をその後に固定。
- 6地域への正確な配置と章タイトル、各章に残す教材。提案: 2・2・2・1・1・2と章表を起点に整理。
- 10章案の `chapterOrder`・`legacyStageIds`・`requiredUnitIds` の確定表。教材内容の素材参照と進捗移行所属を分離し、実装開始前に重複・欠落なし、最長連続章移行、新規横断教材の非付与を確認する。
- 対応ブラウザと性能基準。提案: 現行Chrome/SafariのPC・スマートフォンで、初回マップ操作が操作開始後2秒以内に可能。
