# 地図の名札と「次の街へ」演出 — UI設計

更新: 2026-10-05  
対象画像: `map-overview-detailed-v2.png`（1920 × 819、以下「新地図」）

## 体験の流れ

1. ある街の全フェーズを終え、修了証の **「次の街へ」** を押す。
2. 修了証を閉じ、教材画面は地図へ遷移する。次の教材は自動では開かない。
3. 出発した街から次の街まで、背景画像内の道と同じ曲線を金色の光が 2.4 秒でたどる。
4. 光が着いた街で名札が 240ms で現れ、小さな金色の `▼` が以後ゆっくり上下する。
5. 利用者が名札をタップして初めて次の教材を開く。

同じ街の途中フェーズを修了したときは、従来どおり次のフェーズを表示する。道の演出は **街をすべて修了して次の街へ進む時だけ** 行う。全街修了時は「世界地図へ戻る」のままとする。

## コンポーネント構成

| 要素 | 表示場所・役割 |
| --- | --- |
| `MapDestination` | 各街に付くタップ可能な名札。街の中心ではなく、建物の屋根・風車・煙突から外した位置に配置する。文字は常に不透明。 |
| `DestinationStateMark` | 修了済みは小さな `✓`、現在地だけは金色の `▼`。未解放は街が未表示の間は名札を描かない。 |
| `JourneyOverlay` | 新地図と同じ座標系の SVG。道路の曲線をなぞる一本の `path` と、先端の淡い光点を描く。タップを妨げない。 |
| `JourneyController` | 修了証から渡された `fromPlaceId` / `toPlaceId` を一度だけ消費して、地図の初期スクロール、道の描画、到着後の名札表示を順に制御する。 |
| `MapViewportFollow` | スマホだけ、光点を画面中央付近に保つようスクロールする。PC は全景固定のためスクロールしない。 |

## レイアウトと視認性

- 名札は既存の地図 UI と同じ羊皮紙系を土台にするが、**背景だけを半透明**にする。背景は `rgba(34, 27, 18, .76)`、1px の金縁 `#e8c87c`、影 `0 2px 8px #0008`。文字は `#fff8dc`、不透明、太さ 900。
- 標準名札は高さ 44px 以上、左右余白 10px、丸み 7px。スマホ縦もタップ領域を 44px 以上に保つ。
- 現在地の `▼` は名札の上中央に置く。幅 12px、色 `#f3c95f`、影 `0 1px 4px #0009`。名札そのものは動かさず、`▼` のみを 10px の振幅、1.6 秒、`ease-in-out` で上下させる。フォーカス中・ホバー中は停止する。
- 動きの軽減が有効なら、道は瞬時に表示して先端の光を止め、`▼` は静止する。到着名札は即時表示する。
- 風車の羽根と煙は新地図の静止物を消した部分に既存アニメーションを合成する。新しい静止画の上に静止した羽根・煙を残さない。既存の 18 秒回転と煙の 6 秒ドリフトを維持し、名札・導線より背面に置く。

## 新地図座標と名札の初期位置

実装では新地図の viewBox `0 0 1920 819` を正本にし、画面倍率で座標を作り直さない。下記は画像を目視して屋根・風車・煙突を避けた名札の**初期アンカー**である。背景画像を組み込んだ後、1440×900 / 1920×1080 / 375×812 / 812×375 の実機相当画面で、建物への重なりを確認して最大 16px の範囲で調整する。

| 街 | 街の到着点 `(x, y)` | 名札中心 `(x, y)` | 配置意図 |
| --- | ---: | ---: | --- |
| 始まりの町 | `(192, 207)` | `(196, 326)` | 左上の町の下、川岸の空きに置く。屋根・見張り台を避ける。 |
| 風車の村 | `(1068, 126)` | `(1070, 270)` | 羽根の下の交差路。風車そのものと上空の煙を覆わない。 |
| 川辺の里 | `(1744, 222)` | `(1714, 368)` | 水車・川・塔を避け、町へ入る前の草地側に置く。 |
| 言葉の宿場 | `(1690, 596)` | `(1693, 727)` | 右下の宿場より下の道際。橋と屋根を避ける。 |

現状、物語で地図上にある目的地は上記 4 か所だけである。第2章以降の座標が未定義の間は、道の演出も上記 3 区間だけに限る。

## 道をなぞる導線

導線は次のようにデータとして持ち、画像上の道に沿った複数点のベジェ曲線を使う。`from` と `to` を直線で結ばない。下記はモックアップ用の初期案で、実装前に新地図へ重ねて調整する。

| 区間 | SVG path 初期案 |
| --- | --- |
| 始まりの町 → 風車の村 | `M 192 207 C 332 253, 402 257, 504 236 S 720 186, 850 196 S 1002 177, 1068 126` |
| 風車の村 → 川辺の里 | `M 1068 126 C 1202 175, 1334 185, 1462 194 S 1622 183, 1744 222` |
| 川辺の里 → 言葉の宿場 | `M 1744 222 C 1818 284, 1804 386, 1752 438 S 1726 538, 1690 596` |

描画は細い金色の芯（2px）と、ぼかした外側（10px・低不透明）を重ねる。`stroke-dasharray` / `stroke-dashoffset` で 2.4 秒の一方向アニメーションにし、逆再生・ループはしない。到着時に 280ms の小さな光輪を一度だけ出す。

## スクロールとタイミング

- PC: 新地図の全景を収める現在の固定倍率を保つ。演出中も地図を動かさない。
- スマホ縦: 現在の「旧最小＋2回」の固定倍率を保つ。出発地点を見せてから、光点の進行に 120ms 先行して横スクロールする。上・下の不要なパンはしない。
- スマホ横: 同じ倍率規則を維持し、必要時だけ横スクロールする。
- 2.4 秒の内訳は、出発の明滅 160ms、道路の追従 2,000ms、到着の光輪と名札出現 240ms。ユーザーのタップまたは Esc で即時に完了状態へ飛ばせる。

## 既存デザインシステムとの整合

- `world.css` の濃紺背景・羊皮紙・金縁・44px の操作対象・`Noto Sans JP` / `Marcellus` を継承する。
- 既存の `map-destination.current` の金色グローは維持し、情報の優先順位を `金色の▼` に限定して強める。
- 既存の風車・煙の `prefers-reduced-motion` 方針に合わせ、旅演出もアニメーションを止めて完了状態を表示する。
- 既存の現在地への自動センタリングは、旅演出中は抑止する。そうしないと開始直後に到着地点へ飛び、道をたどる意味が失われる。

## モックアップ

`journey-design.html` は HTML モックアップで作成した。`/gen-rich-image` スキルはこの環境に無いため、静止画生成ではなく、新地図を背景に UI の重なり・色・導線を確かめられる形にしている。初期状態は「始まりの町を修了し、風車の村へ向かう途中」。ボタンで到着状態へ切り替えられる。
