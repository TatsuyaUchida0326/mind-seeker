# 順路をなぞるアニメーション（2026-09-25）

## 計画（Step 1）

- 目的: 街を修了したとき、前の街から次の街までの順路を線がなぞる。通ってきた順路は線として残し、「次の行き先」と「辿ってきた道」を地図上で見えるようにする
- 地図画像は後で ChatGPT で作り直す予定。**順路は画像に描かず、座標データ（経由点）から SVG の線で描く**。画像を差し替えたら座標だけ直せば済む構造にする

### インターフェース

- 新規 `src/routes.ts`
  - `routeWaypoints: Partial<Record<string, RoutePoint[]>>` … キーは到着側の街 ID。前の街→この街の間の経由点（両端の街は含めない）。未定義なら既定の緩いカーブ
  - `buildRoutePath(from: RoutePoint, to: RoutePoint, waypoints?: RoutePoint[]): string` … SVG の `d` 文字列を返す。経由点なしは垂直方向にずらした制御点で2次ベジェ、ありは経由点を滑らかに通る曲線
- `src/App.tsx`: 街ラベルより下のレイヤーに、修了済みの区間（1..currentIndex）の順路を描く。新しく解放された区間（`stageWithGateOpening`）だけ線をなぞるアニメーション
- `src/learning.css`: 順路の線（縁取り＋金色の線）、なぞるアニメーション（`pathLength=1` と `stroke-dashoffset`）、線が伸び切ってから街名が現れるよう遅延

### 演出の順序

修了 → 地図へ戻る → 順路が約1.2秒でなぞられる → 次の街名がふわっと現れる → 跳ねる

# スマホ対応（横向き）（2026-09-25）

## 計画

- ユーザー判断: スマホは横向きで遊ぶ形にする
- 制約: iPhone の Safari は Web ページから画面の向きを固定できない。Android の Chrome は全画面中のみ `screen.orientation.lock('landscape')` が効く
- 方針
  1. 縦向きのスマホでは「端末を横向きにしてください」の案内を全面に出す（CSS のメディアクエリで出し分け）
  2. タイトルの START（ユーザー操作の瞬間）に、タッチ端末なら全画面 → 横向き固定を試みる。失敗しても無視（iPhone）
  3. 横向きスマホ（高さ 500px 以下の横長）専用の配置: 地図を画面いっぱい・1.6倍に拡大して指で動かせる。開いたら現在の街を中央へ。進捗は左上に小さく、アイテムと能力値はボタンで開く引き出し。教材パネルは右側の全高
  4. 街名ラベルはスマホでは SVG 上で1.6倍にし、画面上の文字 12px 前後を確保
  5. ページタイトルを「マインドシーカー」に
- 確認: 812×375（横）・375×812（縦）・1440×900（PC の回帰）で実測。Step 3・5 はテストランナー未導入のためスキップ

## 実装・確認結果

- 実装（サブエージェント）: 縦向き案内（Root）、Android の全画面＋横向き固定の試行（Opening の START 押下時）、横向きスマホ配置（App / learning.css、判定 `(orientation: landscape) and (max-height: 500px)` を App.tsx の定数と CSS で共有）、ラベル1.6倍、アイテム・能力値の引き出し、教材パネル右側全高、タイトル「マインドシーカー」
- PC 確認で見つけて直したもの
