# 順路をなぞるアニメーション（2026-09-25）

## 計画（Step 1）

- 目的: 街を修了したとき、前の街から次の街までの順路を線がなぞる。通ってきた順路は線として残し、「次の行き先」と「辿ってきた道」を地図上で見えるようにする
- 地図画像は後で ChatGPT で作り直す予定。**順路は画像に描かず、座標データ（経由点）から SVG の線で描く**。画像を差し替えたら座標だけ直せば済む構造にする

### インターフェース

- 新規 `src/routes.ts`
  - `routeWaypoints: Partial<Record<string, RoutePoint[]>>` … キーは到着側の街 ID。前の街→この街の間の経由点（両端の街は含めない）。未定義なら既定の緩いカーブ
  - `buildRoutePath(from: RoutePoint, to: RoutePoint, waypoints?: RoutePoint[]): string` … SVG の `d` 文字列を返す。経由点なしは垂直方向にずらした制御点で2次ベジェ、ありは経由点を滑らかに通る曲線
- `src/App.tsx`: 街ラベルより下のレイヤーに、修了済みの区間（1..currentIndex）の順路を描く。新しく解放された区間（`stageWithGateOpening`）だけ線をなぞるアニメーション
- `src/learning.css`: 順路の線（縁取り＋金色の線）、なぞるアニメーション（`pathLength=1` と `stroke-dashoffset`）、線が伸び切ってから街名が現れるよう遅延

### 演出の順序

修了 → 地図へ戻る → 順路が約1.2秒でなぞられる → 次の街名がふわっと現れる → 跳ねる

### 過去の教訓 → 今回確認すること

- `見た目の制約は実測で詰める` → アニメーションが動いていることを目視ではなく算出値（animationName・stroke-dashoffset の推移）で確認する
- `クリックできるdivはキーボードでは存在しない` → 順路の線は装飾。操作要素にせず `pointer-events: none`・`aria-hidden` にする
- `レビューの重ね回しはPRの性質で決める` → 範囲の小さい変更なのでレビューは各担当1回
